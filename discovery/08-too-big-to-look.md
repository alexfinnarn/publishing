Irreducibility says the shortest way to know the outcome is to run the
computation. The working loop is run → look → step. That does not say
the computation can be any size.

A classifier is a fake shortcut: it claims you do not need to look.
An unbounded request is the other fake: it claims you can still look
after a run that mixed too many jobs.

A person given too many tasks and a model given a kitchen-sink prompt
fail in the same *shape*. The person drops, stalls, or does all of them
badly. The model completes. Both produce something you cannot use as
the basis for the next step.

Tomorrow, write into this:

**Name one request — to a model or to a person, including yourself —
that was too big to look at after the run. What mixed. What a smaller
run would have left visible. Was the limit tokens, time, or the number
of jobs inside the ask?**

Not context windows as a product. One ask. Input size and request size
are not the same: a long paste can be one job; a short sentence can be
ten.

Write under the question. Ignore the prompt if a better sentence shows
up.
