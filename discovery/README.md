# Discovery

Dated prompts and replies. Not public. Not drafts for the Site.

The writer answers underneath the prompt, in the same file. Link whatever
is needed *around* the question — ontology, `site/`, a previous note, a
living list in `references/` — so the reply can stay in one place.

Living lists (sites, sources) do not live here. Point at `references/`
and update that file when a URL moves.

## A file

`NN-slug.md`. Next number after the last file. Frontmatter:

```yaml
---
title: Short name
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

Then a short setup with the links this question needs, the questions, a
horizontal rule, and space for the reply.

One prompt per file. If the reply opens a next question, that is a new
numbered file.

## How to write the next prompt

For an assistant (or for later-you):

- Read the last discovery file and the files it already links.
- Ask from their last reply: what they opened, and what they left hanging.
  The gap is in that writing, not in a list of topics this folder has not
  covered.
- Prefer a line of questions over instructions, declarations, and what the
  answer must not be. A worksheet is the same rigidity with question marks.
- Link only what they will need while answering. Do not dump the whole
  workspace.
- Use their language as much as makes sense. If they named a type
  (`Impression`, `Lesson`, `Problem set`), use that word and link
  `ontology.md` or `site/pages.md`.
- Leave their old replies alone. Discovery is the pass, not the spec.

The writer can ignore the prompt.

`site/` and `ontology.md` change when the public surface or the types
change. This folder only has to stay readable.
